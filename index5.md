#  Web Application Vulnerability Detection with OWASP ZAP

**Project Type:** Web Application Security / Vulnerability Assessment  
**Tools Used:** OWASP ZAP, DVWA (Damn Vulnerable Web Application)  
**Status:** Completed  
**Tags:** `OWASP ZAP`, `Web Security`, `Vulnerability Scanning`, `Ethical Hacking`

---

##  Project Overview

This project focuses on understanding and utilizing **OWASP ZAP (Zed Attack Proxy)**, a widely-used open-source tool for detecting security vulnerabilities in web applications. The objective was to set up OWASP ZAP, perform vulnerability scans on a deliberately vulnerable web application, and analyze the results to identify common security issues.

---

## Tools & Setup

- **OWASP ZAP:** Installed on a local machine to perform scans.
- **DVWA (Damn Vulnerable Web Application):** Deployed locally to serve as the target for scanning.
- **Operating System:** Windows/Linux environment for running both tools.

---

##  Methodology

1. **Installation:** Set up OWASP ZAP following the official guidelines.
2. **Target Configuration:** Deployed DVWA locally to simulate a vulnerable web application environment.
3. **Scanning Process:**
   - Configured OWASP ZAP to proxy through the browser.
   - Initiated both passive and active scans on DVWA.
4. **Analysis:** Reviewed the alerts and reports generated by OWASP ZAP to identify vulnerabilities such as:
   - SQL Injection
   - Cross-Site Scripting (XSS)
   - Security misconfigurations

---

##  Key Findings

- **SQL Injection:** Detected in multiple input fields, indicating lack of proper input validation.
- **XSS Vulnerabilities:** Found in comment sections, highlighting the need for output encoding.
- **Security Headers:** Absence of critical security headers like `X-Frame-Options` and `Content-Security-Policy`.
